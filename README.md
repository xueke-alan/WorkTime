# HWorkTime · 工时记录

用于记录上下班时间、统计工时与加班，查看月度目标进度。

- 记录上下班、跨日打卡、请假和计划加班，支持批量填写、时间模板及模板分享导入。
- 导入 OA 考勤记录，统计总工时、平均加班和月度加班目标。
- 自定义工作时间、休息时段和加班要求，按日期范围安排作息。
- 提供月历、年度热力图、下班倒计时、天气、节日和历史事件展示。
- 右栏底部提供游戏分页；可进入覆盖三栏的 2048 游戏空间，使用方向键或 WASD 操作，也支持滑动，不显示屏幕方向按钮。提供单步撤销、自动续局与最高分。返回菜单或退出后继续工时记录。
- 第二款游戏扫雷采用随主题变化的扁平棋盘，提供初级（9×9／10 雷）、中级（16×16／40 雷）、高级（30×16／99 雷）。首击及周围一圈安全，支持右键／长按插旗、开格与插旗模式、点击数字快捷开格，以及方向键移动、Enter 开格、F 插旗。手机大棋盘可滚动浏览。
- 数据在浏览器本地保存，支持备份导出、恢复和历史快照。
- 支持简体中文、繁體中文-台、繁體中文-港、English、한국어、日本語，首次匹配浏览器语言；在“我的设置”中切换并保存偏好。日期和数字按所选语言显示，工时数值单位统一使用 h、m、d、h/d，保留中国考勤规则与业务时区。
- 中文界面保留农历黄历；两种繁体版本分别使用当地用语。韩、日的历史正文使用英文离线快照，并标明正文语言；中文历史有简体及两个繁体版本，均按月份加载。

## 扩展游戏

花了个花的新牌堆采用收边主堆、半格错位的局部高层与左右两列侧叠牌，避免完整底板叠出整齐网格。牌面按实际遮挡深度压暗，牌边与接触阴影显示上下关系，侧堆露出层层薄边。布局版本随棋局保存；不带版本号的旧存档继续原布局，新旅程、下一关或原局重试使用新版牌堆，通关星级保留。

花了个花的背景、布局和动画参考《羊了个羊》的[草地棋盘界面](https://www.9game.cn/yanglegeyang/7109660.html)：浅绿草地、黑底关卡牌、奶油色立体叠牌、木栅栏卡槽、底部三个蓝色道具按钮。保留本项目的 27 种原创角色及 18 关玩法；移出按钮可将托盘末张牌暂存，也可直接点击托盘牌精确选择。取牌飞入卡槽，同类牌滑动归组、聚拢缩小并产生碎粒，余牌补位；撤回反向飞回，换关有入场动效。缩放、暂停及退出会结束动画并显示已保存的最终状态，减少动态效果或动画 API 不可用时直接完成操作。

花了个花沿用公共游戏界面、主题和六语言，提供三章共 18 关层叠三消、27 种原创花园／森林／池塘小角色。前三级保持旧布局和存档兼容，后续使用交叉、环形、斜带、开窗等结构，逐步增加到七层与每局最多 16 种图案。只能取未被上层遮挡的牌，七格托盘内同类三张自动消除；两格可反复使用的暂存区用于调度。各章每关的提示和撤回分别为 3、2、1 次，已用次数不退还。通关得一星，不用提示和不用撤回各加一星；顶部关卡数字可回选已解锁关卡，保留最高星级。随机布局生成时保留无需道具的通关路线，提示不保证余局可解。原局重试保留布局，新旅程更换布局。无倒计时，使用独立存储键 `worktime.games.garden.v1` 自动保存当前关卡和通关记录，支持方向键及 Enter／空格操作。棋盘自适应可用高度，手机及横屏主界面无需滚动。专项验证：`node scripts/verify-garden.cjs`，可追加发布产物目录，覆盖 18 关生成与完整通关、27 种插画、星级及解锁、暂存、撤回、存储异常、六语言及一屏布局。

连连看提供「禅意」「闯关」「潮汐」三种模式，沿用公共游戏界面、主题和六语言。相同图案可通过至多两次转弯的路线连接，允许绕棋盘外侧；三轮均使用固定的 20 列 × 12 行长方形棋盘，共 240 格；棋盘按游戏区域的可用宽高自动适配，窄屏会将棋盘转为竖向排列，全部 240 格、仪表与操作按钮均在一屏内显示，无须滚动。禅意不限时，提示与洗牌无限，换位仍消耗能量；闯关与潮汐限时 150 秒，每对补充 4 秒，新一轮补充 45 秒（上限 240 秒），六秒内连续消除可获得最高五倍连击。潮汐每次消除后轮换重力方向，目标旁箭头按当前屏幕方向显示下一次移动。配对卡片先淡出，剩余卡片再按稳定顺序沿潮汐方向平滑移动，重复图案也保留各自的移动轨迹；动画期间停止计时与连击倒计时。暂停、帮助、窗口尺寸变化、退出或开启减少动态效果时，动画立即落到最终棋盘，存档不会记录中间状态。每轮提供三次提示、两次洗牌，道具中断连击，死局免费重排。动物卡片扩充至 48 种，分为伙伴、森林、海洋、草原四族群，每个新棋盘均包含全部种类且成对分布。绿色角标标记当前收集目标；完成三对目标族群可获得 600 分、2 能量，限时模式另补 8 秒，再轮换目标。每轮初始 3 能量，消除一对获得 1 能量，上限 6；花费 3 能量可主动交换两张不同的牌，打开路线。每对基础 100 分，直连额外 60 分，一次转弯额外 30 分，绕外侧额外 40 分，路线分再乘连击倍率；完成一轮另奖励 500 分。分别记录各模式通关最高分。进度独立保存在 `worktime.games.link.v1`；暂停、帮助与页面隐藏时停止计时，退出再进入时手动继续。方向键移动焦点，Enter／空格选择图案。专项验证：`node scripts/verify-link.cjs`，可追加发布产物目录，覆盖独立路径对照、整盘消除、三模式通关、存储异常及手机布局。

游戏框架不读取或保存工时数据；游戏模块可独立保存自己的进度。2048 使用本地存储键 `worktime.games.2048.v1` 保存棋局、分数、最高分和单步撤销快照，不包含在工时备份中。存储不可用时仍可游玩，并显示无法保存提示。菜单由注册表生成，右栏菜单和展开后的菜单共用同一份注册项。

扫雷使用独立键 `worktime.games.minesweeper.v1` 保存棋局、难度、累计用时、手动暂停状态以及各难度的最佳时间和通关次数，同样不包含在工时备份中。从首次开格开始计时；手动暂停时遮住棋盘，页面后台或退出游戏时停止计时，重新进入可续局。计时每五秒及每次操作、暂停、退出时保存。打开全部非雷格即通关，无须插满旗帜；错误插旗后的数字快捷开格仍可能触雷，首击之后的局面可能需要猜测。

游戏控件及菜单采用统一的扁平 UI：纯色表面、细边框和明确的选中态，按钮按下时不发生位移；跳一跳的场景单独使用立体平台。玩法说明收进 `?` 帮助屏幕。主界面保留棋盘、操作和纪录；确认与帮助覆盖当前棋盘区域，结束提示及存储警告预留位置，避免游戏中界面跳动。扫雷查看帮助时也停止计时。

贪吃蛇提供经典、穿墙、疾速三种模式，采用 24×20 长方形棋盘，各模式分别记录最高分。两颗红色食物任选其一，获得 10 分并增长一格，随后整组刷新；剩余空间不足时只生成一颗。生成位置优先考虑当前蛇身下的可达路线、区域容量和两颗食物的间距，拥挤时逐级放宽条件。每吃 4 个逐步提速，每吃 5 个且没有活动奖励时，生成金色限时奖励；时限参考当前路线距离，已有奖励不会被替换。连续吃到奖励依次获得 50、100、150、200、250 分，最高保持 250 分，超时则连击归零；普通食物不打断连击，金色奖励不增加长度。顶部显示连击档位，奖励旁标注当前分值，不在棋盘下常驻说明。支持方向键、WASD、连续滑动和触屏方向按钮，可缓冲两次转弯，禁止直接掉头。Canvas 使用固定步长模拟与逐帧插值表现连续运动、边缘穿越和吃食物碎粒，减少动态效果时关闭插值和碎粒。独立存档键为 `worktime.games.snake.v1`，兼容旧局并补齐第二颗食物和连击字段；后台、失焦、退出及查看帮助会暂停，继续前有倒数。棋局每三秒及吃食物、暂停、退出时保存，刷新后恢复到最近一次保存。

游戏控件图标来自 Google Material Symbols Rounded（包含棋盘旗帜、地雷、方向键、撤销、帮助及暂停），由 `assets/icons/material-symbols.json` 记录官方来源与内容哈希，并内嵌为离线 SVG。菜单使用注册表内置的简约线条图标。难度选择沿用网页设置的下拉菜单外观与操作方式：键盘导航、选中勾选、Escape 关闭、点击外部关闭；控件高度、圆角、字号和图标尺寸使用网页公共变量。

扫雷按游戏区域的实际宽高共同计算格子尺寸。三档难度共用固定的顶部布局，剩余雷数、用时、最佳时间和通关次数以四张小卡片展示；切换难度只调整下方棋盘，使用 300ms 尺寸过渡，支持快速连续切换，并遵循减少动态效果设置。桌面优先完整展示棋盘；手机中高级保留至少 32px 格子，滚动限制在棋盘内部。

1. 在 `assets/js/games/` 新增独立模块，参考 `2048.js` 调用 `WorkTimeApp.games.register({ id, nameKey, descriptionKey, icon, create })`。`id` 必须唯一；名称及描述的翻译键需加入六种语言；`icon` 默认使用 Material Symbols 的 `sports-esports`，也可填写已有官方图标名。`2048-rules.js` 提供不依赖界面的规则及可注入随机源，供独立测试。
2. `create({ container, signal })` 是同步工厂，只在传入的 `container` 内挂载内容，返回必需的 `dispose()` 及可选的 `resize({ width, height })`、`pause()`、`resume()`。尺寸是扣除容器内边距后的可用 CSS 像素；尺寸回调和暂停、继续方法应允许重复调用。
3. 在 `index.html` 中引用模块，放在注册表之后、应用启动之前。保持经典脚本，不依赖网络加载，确保双击 HTML 与发布打包均可使用。
4. 新游戏沿用 `game-session`、`game-hud`、`game-stat`、`game-button` 和统一的扁平视觉规范，使用 `WorkTimeApp.games.paintCounter` 绘制固定仪表数字、`WorkTimeApp.games.createHelp` 提供按需查看的玩法。以棋盘为主，避免常驻长说明；确认和帮助使用覆盖层，状态及警告预留空间，并验证操作前后棋盘几何位置不变。

返回菜单、切换游戏和退出都会先中止 `signal` 再销毁实例。使用信号管理事件监听，在 `dispose()` 中释放剩余定时器、动画循环、观察器等资源。页面隐藏时容器调用 `pause()`，恢复可见时调用 `resume()`；退出动画期间保持暂停。

验证命令：`node scripts/verify-games.cjs`；可传入发布产物目录验证打包版本。测试使用无界面 Edge，也支持通过 `WORKTIME_BROWSER_CHANNEL` 指定浏览器通道。

扫雷专项验证：`node scripts/verify-minesweeper.cjs`，同样接受发布产物目录；覆盖纯规则、存档、计时、胜负纪录、鼠标／触摸／键盘、主题、多语言及游戏切换。

贪吃蛇专项验证：`node scripts/verify-snake.cjs`，同样接受发布产物目录；覆盖纯规则、转向缓冲、碰撞与穿墙、限时奖励、满盘胜利、存档、暂停续局、六种语言和响应式布局。

数独提供简单、中等、困难、专家、奇偶数独、温度计数独六组，各 20 关，共 120 关。每组内部按顺序解锁，所有组的首关均可进入；支持候选笔记、擦除、撤销、提示、暂停、重玩确认和下一关。每关分别自动存档，记录用时和提示次数；重玩保留通关记录。键盘方向键选格、1–9 填数、N 切换笔记、Delete 擦除、Ctrl / ⌘ + Z 撤销。界面沿用公共游戏按钮、仪表和帮助页，支持六种语言、主题及手机布局。

题库来自 [Sudoku Exchange Puzzle Bank](https://github.com/grantm/sudoku-exchange-puzzle-bank)，已按其公有领域许可内置到 `assets/data/sudoku.js`，无需联网即可游玩。普通四组按上游 Sukaku Explainer 评分由低到高排列；特殊两组在不同的上游题目上增加奇偶或温度计约束，再尝试移除最多 10 个原始给定数，每次移除均验证唯一解。特殊组的评分是原始经典题评分，不代表特殊规则下的人类解题难度。来源、文件校验值、原题标识、原始给定数和许可证均保留。

数独专项验证：`node scripts/verify-sudoku.cjs`（可追加发布产物目录）；覆盖 120 道题的唯一解、独立行列宫校验、特殊约束、输入、存档恢复、解锁、计时、六语言、手机和禁用存储场景。重新从网络导入题库：`node scripts/import-sudoku.cjs`，此操作不属于正常启动或发布构建流程。

推箱子提供 60 关，分为「初识仓库」「巧妙周转」「步步为营」三章，各 20 关；完成上一关解锁下一关，可重玩已解锁关卡。沿用公共游戏界面、主题和六种语言，支持方向键、WASD、棋盘滑动和触屏方向按钮，以及连续撤销（Z）、重玩确认（R）、非目标墙角卡死提示和下一关。每关分别自动续局，独立存储键为 `worktime.games.sokoban.v1`；通关纪录以推动次数优先、步数次之，重玩和撤销不会取消已取得的解锁。存档通过重放合法操作验证，存储不可用时仍可游玩。

推箱子题库来自 David W. Skinner 的 [Microban](https://www.onlinespiele-sammlung.de/sokoban/sokobangames/skinner/)，按作者「保留署名即可分发」的条款内置；原始文本、作者、来源编号和 SHA-256 均保留，许可说明在 `licenses/microban.txt`。从原题前 100 关中选取 60 道经求解验证的关卡，保持原图，按最少推动次数从 1 到 50 递增排序。该指标用于难度渐进编排，不等于人类解题难度的严格排序。题库、解法和全部资源均离线内置。

推箱子专项验证：`node scripts/verify-sokoban.cjs`（可追加发布产物目录），覆盖 60 关来源一致性、解法重放、规则、解锁、自动续局、重玩、撤销、六语言、触屏和存储异常。从本地原始文本重建题库：`node scripts/import-sokoban.cjs`；追加 `--fetch` 才会重新联网下载。导入采用推动状态广度优先搜索，因而已求解题目的最少推动次数可验证；搜索上限内未求解的原题会跳过，导入不参与正常启动或发布。
