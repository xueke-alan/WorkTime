# 工作记录

无需安装依赖或构建，双击 `index.html` 即可在浏览器中使用。

工具栏中的“页面设置”提供清新绿、天空蓝、柔和紫、暖橙色、玫瑰红、雾蓝灰六种浅色主题，选择后立即生效并保存在当前浏览器，工具栏、按钮及浏览器标签页图标同步变色。下载及剪贴板备份均包含当前主题色，确认恢复后同步恢复主题。维护时可运行 `npm run test:theme` 验证主题切换、保存、备份恢复与缩放布局。

开发时，主题标识与颜色维护于 `assets/js/domain/preferences.js`，独立偏好状态与保存操作维护于 `assets/js/services/preferences.js`；`theme.js` 负责呈现。主题保存不改写工时记录，备份从偏好状态快照读取当前主题。

右下角“天气”标签按设置中的工作城市显示百度实时天气及接口实际提供的预报。
当前支持东莞、上海、深圳、成都、西安、南京、杭州、北京、武汉、苏州；数据由 GitHub Actions 计划于每小时第 7、22、37、52 分钟采集，前端读取公开 JSON，
断网时显示最近缓存。首次发布与增加城市的方法见 [天气说明](docs/WEATHER.md)。

日历卡片只显示北京时间今天及后续四天的天气，共五个自然日；跨月相邻日期也遵守同一范围。

为避免多个页面相互覆盖记录，保存使用浏览器 Web Locks 单写者锁。建议使用新版 Edge 或 Chrome；同一浏览器同时打开时，只有取得写入锁的页面可以保存，其他页面可查看、修改并导出备份。关闭其他页面、备份当前未保存修改后刷新，可以重新取得写入权。浏览器不支持锁时会明确提示无法保存。

## 开发与重构

用户运行无需 Node。维护时使用 Node 22.13 及以上，`npm ci` 安装锁定的开发依赖；`npm test` 运行业务测试，`npm run check` 检查 JS 语法，`npm run lint` 检查维护代码，`npm run check:format` 检查格式。`npm run test:browser` 运行 Edge 无界面回归，`npm run test:styles` 比较 66 组整页、88 组资讯、88 组统计及 154 组日历及330组编辑器/弹窗状态的计算样式和位置。样式基线来自 Windows Edge，依赖本机字体；跨平台结果需先核对环境，不能直接覆盖基线。模块契约见 `docs/ARCHITECTURE.md`。

## 文件结构

统一门禁为 `npm run test:all`，包含语法、质量、单元、Python、浏览器、严格样式和离线资源检查。入口在运行前后核对 `docs/` 与 `tests/fixtures/` 的文件指纹：新增、修改或删除这些证据文件均视为失败；测试截图和报告写入忽略跟踪的 `test-results/`。

性能测量方法见 `docs/PERFORMANCE_CONTRACT.md`；`npm run benchmark -- --samples 20 --output test-results/performance-new.json` 可独立复测，`npm run trace -- test-results/performance-trace-new.json.gz` 可采集诊断。加入 `--snapshot` 使用本轮保护快照和同一测量方法，先核对原始文件哈希，并断言新旧规模的记录、导入、排班和模板语义一致；正式前后测量应串行进行，报告分别绑定被测源码与当前测量工具。运行产物写入 `test-results/`，不得覆盖历史基线。原生浏览器缩放可使用 `node scripts/review-native-zoom.cjs <唯一输出标签>`，使用临时配置并保留证据，不修改日常浏览器设置。历史快照只保存在本地，`--snapshot` 需本机已有对应快照。

- `assets/css/layout.css`：工作区、整体页面和页脚的响应式布局。
- `assets/css/editor.css`：单日/批量编辑器、请假浮层、模板列表和共享次日开关。
- `assets/css/dialogs.css`：弹窗容器与模板、设置、导入、恢复等特有结构。
- `assets/css/date-info.css`：资讯页签、历史、节日、黄历及倒计时样式，含组件断点与隐藏/焦点契约。
- `assets/css/summary.css`：统计侧栏、汇总卡片、目标区、数字与单位，以及组件响应式规则。
- `assets/css/calendar.css`：月历、年历、工具栏和图例；按日历容器宽度排版，短窗口月历可内部滚动，见 `docs/CSS_CONTRACT.md`。
- `assets/css/controls.css`：时间、数值输入框与同类按钮的公共视觉样式。
- `assets/js/domain/`：日期值、状态、日历、记录计算、统计、OA 解析回放和备份校验。
- `assets/data/calendars.js`：2020–2026 调休安排及官方来源、覆盖范围和核查日期。
- `assets/js/domain/types.js`：业务输入、输出与状态结构的 JSDoc 契约。
- `assets/js/namespace.js`：唯一项目命名空间 `WorkTimeApp`，包含 `domain`、`services`、`ui` 和 `data`。
- `tools/convert-backup.html`：可离线打开的一次性旧备份转换工具，输出版本 3 备份。
- `assets/js/ui/`：日记录展示、统计、日历、编辑器与通知视图，通过 getter 获取当前状态。
- `assets/js/controllers/`：模板、设置、备份、导入、单日编辑、导航/批量和通用弹窗的事件控制器。
- `assets/js/services/`：启动错误边界、集中应用/导航状态、注入时钟、剪贴板与下载适配器。
- `services/derived.js`：按内存数据版本共享统计结果，保留未保存更改和临时预览的正确性；`services/import-index.js`缓存来源日期查找，原文日期与已接受记录分开。
- `assets/js/app.js`：初始化与依赖连接入口；控制器构造完成后统一注册事件。
- `assets/css/motion.css`：动画行为和关键帧；时长、缓动由tokens.css定义，不使用悬停浮起、悬停阴影增强或按下缩小效果。
- `assets/js/motion.js`：首次入场和明确交互的动画触发；普通保存、输入及倒计时刷新不重播，遵循系统减少动画偏好。
- `assets/js/background.js`：背景粒子动画，遵循系统减少动画偏好。
- 倒计时复用内容节点，仅更新变化的文字；切到其他页签或隐藏页面后停止计时，返回时立即校时。背景粒子随页面可见性与运行中的减少动画偏好暂停/恢复，退出时统一清理。
- `assets/js/ui-alignment.js`：保留日历数字与特殊文字的字形校正；普通按钮按实际字号分类使用公共 CSS 行高和补偿，不按内容计算偏移。`tests/button-ink.browser.cjs`检查24宽度×4 DPR×3类按钮，共288组的实际字形中心和共同基线，并比较同一字号下文字补偿前后的图标与点击区域。
- `licenses/material-symbols.txt`：Material Symbols 图标来源与 Apache 2.0 许可证。

经典脚本按 `index.html` 中的显式依赖顺序加载：首先声明 `WorkTimeApp`，其后加载数据、领域、服务、界面和组装入口。不要改为异步加载或 ES Modules，以保留双击运行方式。SVG 图标保留在页面中，避免本地文件的跨文件引用限制。`node scripts/sync-material-icons.cjs --check` 从固定官方提交核对全部图标及清单，不写文件；去掉 `--check` 后先验证完整下载，再替换页面和清单，写入失败时回滚。来源提交与逐图标哈希保存在 `assets/icons/material-symbols.json`，许可证见 `licenses/material-symbols.txt`。

## 数据与迁移

记录保存在当前浏览器的 localStorage 中，存储键为 `worktime-local-v1`，当前数据版本为 3。请定期下载 JSON 备份；旧备份先使用 [独立转换工具](tools/convert-backup.html) 输出版本 3 文件，再通过应用恢复。转换不改写原文件或浏览器存储，步骤见 [备份转换说明](docs/BACKUP_CONVERSION.md)。

存档损坏时，页面使用临时默认数据并保护原存档，可在“信息与提醒”中导出原始数据、恢复备份，或确认放弃旧存档后初始化。初始化清空工作记录及工作设置，保留页面主题，不影响其他浏览器存储。访问失败时请恢复浏览器存储权限后点击“重新检查”；已有临时修改时先下载当前页面备份再刷新。版本不兼容时使用转换工具。恢复和初始化仅在写入成功后替换正式数据；失败时保留原数据和确认框，可重试。主题单独保存失败时可点击“重试保存主题”。

恢复时会校验记录、设置、模板、个人信息、偏好与导入历史，错误提示包含具体字段路径。运行时拒绝不支持的版本；非法时间或不合法记录不会静默改写后恢复。初始化失败时页面提示错误并禁用操作，请检查项目文件是否完整后重新打开；此时不会用默认数据覆盖原有存储。

移动或分发时请保留整个目录及相对路径，不能只复制 HTML。移动位置、切换浏览器或清理浏览器数据前先备份，之后按需恢复；本地文件的存储行为取决于浏览器。恢复备份会替换当前浏览器中的记录和设置。

## 月度加班条件

计算设置中配置最低要求及非工作日加班 1、2、3、4 天及以上的要求，单位为小时/折算出勤日。新建存档的五档默认值为 1、1.5、1.5、2、2 小时/折算出勤日；已有存档保留原设置，适用档位为空时需先配置。非工作日可标记计划加班，有完整有效工时的日期计为实际加班，与计划同日去重。调休补班按工作日处理。非工作日工时只影响档位，仍单独统计，不抵扣工作日目标。

计划与条件保存在 JSON 备份中。独立工具转换旧备份时仅保留最低要求，其他档位为空。运行 `node tests/monthly-requirements.test.cjs` 可验证规则与转换契约。

历史月份或没有剩余可分配工作日时，目标区保留差额、已达标或超出目标；每日分配显示 `0.0`，以保持数字动画精度。缺少工作日记录时显示缺数据说明，正差额标为“记录内差额”，补齐后才显示“未达标差额”。不会因为月份结束把差额改为零。

应用中的“今天”和当前年份使用中国标准时间，与下班倒计时一致。跨午夜或从休眠恢复后会刷新统计、日历与通知，保留当前选中的日期和正在填写的输入；点击“今天”再跳转到当前日期。

## 本地日期资讯

右栏底部提供通知、历史上的今天、节气及节日、农历黄历图标页签；内容跟随选中日期。所有资料保存在项目内，离线可用。农历和黄历支持 1900–2100 年，黄历为传统民俗参考。资料来源与扩展方式见 `assets/data/README.md`。运行 `node tests/date-info.test.cjs` 验证资料及日期规则。

## 下班倒计时

时钟图标页签始终计算中国标准时间的当天，不跟随日历选中日期。使用当天作息的标准下班时间；“常规下班”模板仅用于填写打卡，部分请假不改变标准下班时刻。休息日且无计划加班或完整工时记录时不倒计时，全天请假也不倒计时。到点显示“已到下班时间”，每秒更新；切回页面时恢复实时计算。标准作息暂不支持跨午夜，实际打卡仍支持次日下班。运行 `node tests/work-countdown.test.cjs` 验证规则。

## 发薪日

实际发薪日期的日历卡片在日期数字右侧显示红色圆形人民币图标，不提供独立页签。图标提示显示实际日期；提前时说明原定日期及提前天数。每月15日发薪；遇节假日或周末，提前至最近的工作日，调休补班日按工作日处理。使用内置2020–2026年调休日历，覆盖外年份暂按周末及七类主要节日当天休息推算；个人请假或计划加班不改变发薪日期。运行 `node tests/payday.test.cjs` 可验证规则。

## 年视图

点击日历左上角的年月，在月视图与全年热力图间切换。年视图左右箭头切换年份；点击日期返回对应月份并选中当天。加班颜色按所选年份的 0 小时到最长加班时长向上取整后的整数小时连续渐变，其他时长按比例插值；无完整记录使用零值颜色；欠工时使用红色连续渐变，负数下限按最少记录向下取整到整数小时，年视图只展示加班颜色，点击日期查看详情。每个月上方显示月份标题，切换年／月视图时使用渐显动画，并遵循系统减少动画设置。侧栏统计和目标仍对应原来选中的月份。

运行 `node tests/year-view.test.cjs` 验证全年日期和热力图规则。已安装 Playwright 与 Edge 的环境可运行 `node tests/year-view.browser.cjs` 验证交互和响应式布局。

右侧预览的应出勤工时、已出勤工时、平均加班与入职天数同样使用滚动数字动画，遵循减少动画设置。平均加班缺失时也显示零小时，汇总卡片固定三位小数（`0.000 h`），预览固定两位小数（`0.00 h`），与非零值保持一致。

OA记录在左栏显示：点击OA记录切换到导入视图，导入历史及记录详情沿左栏逐级打开，返回保留未提交文本；取消或完成导入回到工时概览。日历和右侧编辑区保持可用，小屏视图在概览原位置展示。

## 按日期范围应用作息

计算设置载入日历选中日期的作息。上下班时间与休息时段先作为草稿编辑，右侧日历按钮打开“应用作息”弹窗；选择全部日期、从今天起、今天起7个自然日、今天至月末或自定义范围，点击应用后保存。有限范围包含首尾两天，中国标准时间的今天在打开弹窗时固定。自定义范围可不设结束日期。

范围内替换已有作息，范围外保留原安排；临时范围结束后恢复该日原本适用的作息。“全部日期”会统一历史和未来作息并清空区间。作息安排列表可查看并载入编辑，载入不直接修改数据。取消范围弹窗保留草稿，离开设置时可应用、放弃或继续编辑；草稿不随备份或刷新保存。入职日期、城市与加班要求仍为全局自动保存，不会保存作息草稿。

实际打卡、OA原文、手动有效分钟数、请假时长及模板不被作息修改覆盖。范围内请假超过新标准工时会阻止应用并列出冲突日期。按每日作息扣除休息和折算出勤，月度及累计平均加班均为工作日加班总分钟÷完整记录的折算出勤天数之和。折算出勤天数参与领域计算，预览只展示工时、平均加班和入职天数；跨午夜记录使用所属日作息。倒计时使用今天的标准下班时间，“常规下班”模板只用于填写打卡。不同作息日期可以普通批量填写，但“按平均加班填写”需按作息分批选择。

当前数据版本为3，保留存储键与JSON/GZIP备份传输格式。运行时只接受版本3；版本1/2备份先用独立离线转换工具输出新版，再恢复到应用。转换不改写旧文件或旧存储。升级前建议导出原备份。作息保存失败时不应用候选安排，弹窗保留草稿并允许重试。运行 npm run test:schedule 验证业务及浏览器流程。


## 版本管理范围

仓库保留应用源码、离线资源、天气快照、许可证、必要维护文档，以及复现检查所需的测试、固定基线和维护脚本。`tests/fixtures/` 是测试输入，需要随代码提交；`assets/vendor/` 是离线运行依赖，需要保留。

截图、性能采样、历史交付与审计报告、本地备份、依赖目录和测试输出由 `.gitignore` 忽略，不上传 GitHub。本地生成产物统一写入 `test-results/`；历史资料可在本机保留。忽略文件从 Git 索引移除不会删除本地文件，旧版本仍可通过 Git 历史查看。

日历节日标签由 `scripts/sync-major-festivals.cjs` 从随项目分发的农历库生成，不改变法定调休安排。倒计时页签支持专注显示与 Escape 返回；动画兼容与降级行为见 [动画兼容说明](docs/ANIMATION_COMPATIBILITY.md)。
