# 工时记录计算器

双击 `index.html` 即可使用，也可通过 GitHub Pages 在线访问，无需安装或构建。

- 记录上下班、跨日打卡、请假及计划加班，支持批量填写和时间模板。
- 导入 OA 记录，统计工时、平均加班和月度目标。
- 提供月历、年度热力图、天气、节日及下班倒计时。
- 数据保存在当前浏览器的 IndexedDB，支持模块化 JSON/GZIP 备份与恢复；建议定期导出备份。

推荐使用新版 Edge 或 Chrome。同一浏览器同时打开多个页面时，只有取得写入锁的页面可以保存；不支持写入锁时，事务内修订号检查阻止冲突覆盖。

首次打开会自动识别并转换旧 schema 1、2、3 存档，成功写入并回读后才开放保存。旧 `worktime-local-v1` 和迁移原文均保留；旧版文件也可直接恢复，或通过 `tools/convert-backup.html` 单独转换。

## 存档与恢复

双击文件与网站地址不共享存档。移动文件、换浏览器、换设备或切换访问地址前，请导出备份；`file://` 的存储隔离取决于浏览器。浏览器清理数据会同时删除主存档与内部快照，内部快照不能代替外部备份。

页面提供“历史快照与恢复资料”：当天首次修改前保存日常快照，最多 7 份；恢复和初始化前保存操作快照，最多 3 份。两类合计上限 100 MiB，按时间淘汰旧快照。迁移原文独立保留，不自动删除。恢复前快照无法保存时拒绝替换，可下载恢复资料或清理历史快照。

IndexedDB 不可用时显示临时模式，修改可导出，不能保存。损坏的存档可下载恢复资料后恢复兼容备份；未来版本进入只读保护，只允许下载原文，需使用支持该版本的应用处理，禁止降级覆盖。旧页面再次修改遗留存档时显示冲突，提供旧数据重新导入入口，不自动覆盖新记录。

备份包括工时、导入历史、个人信息和长期偏好（主题、天气展示模式）；不包括天气缓存、当前标签页、未提交表单、快照及迁移原文。JSON 是基础格式；支持压缩 API 的浏览器可复制 GZIP 文本。输入文件和解压内容默认各限 100 MiB，这一限制可在备份读取接口配置，不属于格式约束。

## 稳定数据格式与扩展约定

备份外层固定为 `format: "worktime-archive"`、`formatVersion: 1`、`archive` 和 `modules`。`archive` 包含稳定 UUID `id` 与 ISO `createdAt`；导出可附带 `exportedAt`。模块具有命名空间 `id`、独立整数 `version` 和 `records`；记录具有字符串 `id`、顺序 `order` 及对象 `data`。外层、模块、IndexedDB 数据库和应用发布版本相互独立。

首批模块为 `worktime.profile`、`worktime.rules`、`worktime.schedule`、`worktime.days`、`worktime.templates`、`worktime.imports`、`worktime.observations`、`worktime.evidence`、`worktime.preferences`。每天的 ID 是日期，作息区间 ID 是起始日期；导入和模板保留历史 ID，新记录使用 UUID；接受的打卡及来源证据以 `[导入ID,序号]` 的 JSON 字符串标识，保持原顺序。

数据库 `worktime-archive` 的版本为 1。固定对象仓库是 `archives`、`modules`、`records`、`snapshots`、`migrations`、`cache`。业务记录主键为 `[archiveId,moduleId,id]`，按档案、模块及导入批次建立索引；新增模块不需要改变数据库结构。档案修订号用于本机并发检测，备份中的修订号不会作为本机写入凭据。

新增功能遵循以下规则：

- 新数据使用新的命名空间模块；运行时投影与数据库记录通过格式适配器连接，不把整个界面状态放进业务数据。
- 添加可选字段时提供默认值，保持模块版本；改变字段含义或删除字段时升级该模块版本。
- 在页面启动前调用 `archive.registerModule(id, {version, migrations})` 注册目标版本及逐版本纯函数。`migrations[n]` 接收独立模块副本，返回版本为 `n + 1` 的模块；函数不得访问存储、网络或 DOM。启动升级会保留转换前原文并事务提交，独立转换器使用同一注册表。
- 未知模块和未知可选字段必须随读取、编辑及备份往返保留。修改记录仅更新模块拥有的字段；未知的已注册未来模块版本或外层版本进入保护状态，不自动降级。
- 使用异步 `load / commit / export / restore / migrate`；`commit` 明确列出涉及的日期、导入 ID 或设置模块，只有事务完成才返回 `persisted: true`。不要依赖页面关闭时保存。事务默认设有 120 秒超时保护，超时取消并保留内存修改。
- 统计、缓存和搜索索引可重建，不作为业务事实。接受的 OA 打卡记录用于历史重放，来源证据只用于核查。

天气缓存在 IndexedDB 中单独保存，最多 10 个城市、7 天；存储容量不足时优先清理缓存并重试一次，不删除业务或迁移原文。localStorage 仅保留遗留存档、主题启动展示缓存和当前标签页等设备状态。

维护：使用 Node.js 22.13+，运行 `npm ci`，通过 `npm run check`、`npm run lint` 和 `npm run check:format` 检查代码。GitHub Pages 自动发布，天气由 GitHub Actions 定时更新。测试、截图及历史审计资料仅在本地保留。

本次本地回归已覆盖 Edge、Chrome 的双击 HTML 与网站模式，以及 Firefox 网站模式；包含旧版本迁移、事务回滚、冲突保护、备份往返和 1/10/30 年样本。Windows Playwright WebKit 的网站功能回归通过，但带复合索引的大批量 IndexedDB 写入在独立原生示例中也出现停顿，压力测试未通过；尚未验证 macOS Safari，不承诺其双击文件兼容。性能结果依赖浏览器、设备和数据规模，不作为所有环境的固定时限保证。

本地迁移和浏览器回归保留在 `tests/archive-upgrade.cjs`，结果在 `test-results/archive-upgrade-*.json`。例如运行 `node tests/archive-upgrade.cjs edge` 验证双击模式，添加 `--http` 验证网站模式；WebKit 使用 `--http --functional-only` 运行功能回归。样本覆盖已有数据契约及边界情况；首次迁移前仍建议导出现有真实存档，以便独立核对。

存档校验按记录身份保留扩展字段，日期打卡按日期关联，避免相同上下班时间串用其他日期的数据。快照列表只读取快照仓库；导入历史已加载时，导出直接使用当前状态，避免重复读取整份数据库。主题与天气偏好的旧保存结果不会覆盖后续操作的状态；日期编辑的旧保存回调不会更新新选中日期的提示。本地 `tests/review-followup.cjs` 覆盖这些回归及统计缓存一致性。
