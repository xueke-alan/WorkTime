# 备份转换和恢复

当前工作记录使用版本 3。工时规则位于 `settings`，入职日期和城市位于 `personal`，备份主题位于 `preferences.pageTheme`。排班区间、日期记录、时间模板和导入历史继续保留；每次导入都包含明确的已接受 `records`，原始来源文本不会作为日常删除批次重放的数据。

旧版数据不会在启动中自动迁移。浏览器已有版本 1/2 数据时，页面显示转换指引并保留原始存储；不要清理浏览器数据。使用“导出无法读取的原始数据”保存旧记录，然后打开 `tools/convert-backup.html`（可以双击离线使用）。

转换步骤：

1. 选择旧 JSON 或压缩文本备份，也可以粘贴内容。
2. 点击“转换备份”。失败时显示具体字段路径，不产生可下载结果。
3. 下载新的版本 3 文件，旧文件不被修改。
4. 回到工作记录页面，选择“恢复”导入新版文件，核对预览后确认恢复。
5. 核对记录、排班、模板、统计和主题，再导出一份新备份保存。

转换页面不读取或写入浏览器存储，不向服务器传输备份。原始文本、已接受记录和空接受列表分开保留；空列表不会重新接受曾被拒绝的原文。对于早期没有接受列表的历史备份，独立转换器按当时的重放规则一次性生成明确记录。

开发实现中，转换页面与应用共用下载适配器；下载失败或页面离开时回收对象URL，页面离开同时取消延迟回收计时器。异步文件读取和转换结果使用当前输入修订标识，输入变更或页面退出后不再显示旧结果。

旧规则模块 `tools/legacy-v2.js` 仅导出 `validate` 和 `acceptedRecords`，保留版本 1/2 的字段校验、工时规范化和缺少接受列表时的历史解析规则；旧迁移、统计、日历和编辑门面已移除。转换后继续通过新版校验，不绕过版本 3 契约。测试使用带 SHA-256 来源信息的冻结旧实现作独立算法对照；它只由测试辅助程序解压加载，不进入转换页面。该对照的日历资料仍由测试环境提供，不能据此声称所有历史资料也被冻结。

发布准备时，`scripts/version-site.cjs`同时处理主页面与转换页，为共享`../assets/`依赖及转换页本地JS/CSS添加内容哈希，避免浏览器混用旧门面和新版转换代码。两个页面的依赖先全部校验，再写发布副本；缺资源使构建失败。工作区离线入口不被此步骤修改，转换仍只在内存进行。

运行时只接受版本 3，不再推断缺失排班、旧单档目标或旧导入日志。主题缺失的旧备份转换为默认绿色；已有主题会保留。普通编辑及恢复写入失败时保留会话数据供重试和导出，排班应用失败时保留原有效规则与待应用草稿。
