优先级定义：P1 为数据可靠性或静默覆盖；P2 为计算展示、日期和视觉正确性；P3 为维护与文档一致性。本次没有确认 P0。

## 4. 已确认缺陷

### R01：保存失败仍显示成功并关闭设置弹窗（P1）

位置：app.js:48、173、229、236、353、372、524。

复现：隔离页面让 Storage.setItem 抛 QuotaExceededError，提交计算设置。页面同时出现“更改未保存”和“计算设置已更新”，弹窗关闭。

原因：save 返回 false，但多处忽略结果。saveDayEdit 返回表单处理成功，也不代表数据持久化成功。内存已变，用户可能关闭页面而丢失改动。

修复任务：统一提交结果 `{ok,persisted,dirty,error}`；分开内存状态与已保存状态；保存失败提供重试和备份，使用准确反馈。检查设置、模板新增/删除、普通导入、快捷导入、删除历史、批量编辑、单日编辑和恢复全部入口。

验收：quota、存储不可访问、损坏存储三类故障下不显示“已保存”；未保存改动可以导出，恢复写入后 dirty 清除。不能只修改单个 toast。

### R02：两页编辑相互覆盖（P1）

位置：app.js:11、48 和各状态修改入口。

复现：同上下文两个页面；A 编辑 10 月 8 日，B 编辑 10 月 9 日。最终仅保存 B 的日期。

原因：页面只在启动读取一次，全量写回旧内存快照，没有写入协调与冲突处理。

修复任务：storage 独立管理 revision、writerId、外部更新和冲突策略。先实现检测外部更新后阻止旧页静默写入，允许导出草稿和刷新；再做串行写入和明确合并。能力允许时使用浏览器锁，不支持环境选择受控单写者或明确阻止提交。

注意：只在写前比较 revision 不是原子 compare-and-swap，storage 事件也不能保证同时提交安全。file:// 下事件与共享存储需在目标浏览器验证。

验收：不同日期、同日期、设置/记录、恢复/编辑同时操作不静默丢数据；冲突可见，失败页面可保留或导出改动。

### R03：备份接受后无法再次校验（P1）

位置：core.js:209、213、221。

复现：声明 standardMinutes=480，但 08:00–12:00、无休息，某日请假 480。首次接受并重算为 240；再次校验输出拒绝请假。

原因：settings 规范化后使用 derivedStandard，days 校验仍用输入 standardMinutes。

修复任务：先迁移并规范化 settings，再以规范化值校验日期字段；不一致备份显式迁移或明确拒绝，错误带字段路径，避免静默改变语义。

验收：所有接受的输入经 serialize/validate 再次有效，统计保持一致。覆盖旧字段缺失、休息重叠、缩短标准工时、部分/全天请假。该故障来自特制备份，未证明常规页面会生成它。

### R04：OA effectiveMinutes 被接受后丢弃（P2）

位置：core.js:80、225、227、228。

复现：OA complete，start/end 为空，effectiveMinutes=480；完整性检查接受，但清洗 OA 时丢弃该字段，输出不完整，再次恢复失败。

修复任务：明确 OA 是否允许修正分钟。建议 OA 保留原始打卡，actual/estimate 才支持修正；OA 分支明确拒绝不支持字段。若允许则完整保留并统一校验。

验收：分别测试 OA/actual/estimate/draft 字段契约；清洗不能丢弃使记录有效的字段。

### R05：快捷剪贴板导入绕过完整记录冲突选择（P1）

位置：app.js 中 parseImport、commitOARecords、importFromClipboard 和 :524 确认路径。

复现：已有 09/28 的 08:00–17:30，快捷导入 08:00–20:00，直接替换且没有预览；普通粘贴路径允许保留旧值。

修复任务：共享 `prepareImport → resolveConflicts → commitImport`。无冲突可快速提交，有完整记录冲突进入统一选择界面。导入日志保留已接受 records，raw 只作为来源，不应重放用户拒绝记录。

验收：快捷/普通入口对重复、补全、完整冲突和异常记录一致；删除其他批次不能复活拒绝项；保留手动覆盖和原始来源。

### R06：“今天”不随跨日刷新（P2）

位置：app.js:14 与 todayButton、pendingWorkdays、导入年份、备份文件名相关路径。

复现：中国时区 10/02 23:59:59 打开，推进到 10/03，点击今天按钮，仍标记 10/02。

修复任务：注入 clock，明确业务日期与 now；跨日、focus、visibilitychange、休眠恢复重新计算今天。明确浏览器本地日期与倒计时中国标准时间的关系。刷新 today 信息时不强迫正在查看历史日期的用户跳走。

验收：跨日/月/年、系统时钟变更、海外时区、休眠恢复；今天按钮、待录入、OA 年份和备份名称一致。夜班归属先制定规则。

### R07：历史月份目标差额被置零（P2）

位置：app.js:80。

复现：10 月查看无记录的 2026 年 1 月；核心 difference=2520 分钟，remainingDays=0，界面指标为 0。

修复任务：累计差额与后续日均要求分开。无剩余日期时日均要求不可计算，但差额保留；缺少记录不能直接宣称实际未达标，应有缺数据说明。

验收：已结束月份的盈余、差额、缺记录、全请假、无工作日均有准确状态。

### R08：已内置年份提示未内置日历（P2）

位置：app.js:113、424。

复现：2025 calendarKnown=true，页面仍说“未内置节假日”。界面把 2026 写死为唯一已知年份，核心实际覆盖 2020–2026。

修复任务：全部使用 calendarKnown 和统一覆盖年份元数据，更新 README 发薪日范围描述。

验收：2020–2026 无缺失提示，2019/2027 有提示；年/月视图与发薪日说明一致。

### R09：同类工具栏按钮按文字内容施加不同位移（P2）

位置：index.html:93；ui-alignment.js:31、50；styles.css:1248、1855；controls.css:53。

## 5. CSS 专项方案

### 5.1 已观察到的结构风险

样式最终效果受 styles → controls → motion 加载顺序、选择器特异性、important、媒体/容器查询、JS 注入 class/inline style 共同影响。不是单条 padding 就能解释所有异常。

源码解析统计见 JSON；important 声明 213 处，空规则 52 条。`.summary-sidebar .cards` 重复 19 次，`.summary-sidebar .card` 14 次，`.summary-sidebar` 13 次。不同条件下重复不一定错误，但组件定义分散增加维护成本。

- 公共按钮高度在基础、桌面、统一尺寸与局部例外多次定义。
- `body button:not(.day)` 影响年视图与页签，后面又增加特殊覆盖。
- 空时钟先采用透明文字+提示层，后恢复原生 placeholder，旧路径残留。
- controls.css:79 给设置输入单独加顶部 padding，同类时钟存在结构差异；需验证视觉后决定，不直接认定每个环境都是 bug。
- ui-alignment 包裹裸文本、改 class/style，并监听 body 全树，排版依赖运行时加工。
- 组合备份按钮内部比独立按钮低约 2 px，是外框结构所致；比较整体外框，不应把它直接列成缺陷。
- 旧 `.top`、more-menu、输入类型相关样式需覆盖动态状态后确认是否可删除。

### 5.2 目标职责

建议文件：tokens、base、layout、controls、calendar、summary、editor、dialogs、date-info、motion。不要机械拆旧文件；先建立某组件唯一规则来源，删除其旧覆盖，再迁移下一组。断点紧邻所属组件，必要例外用 modifier 表达。

控件契约：`.button`、`.button--icon`、`.button--primary`、`.button-label`，固定 icon slot；clock/number 共享输入家族，普通中文 UI 与数字展示区分别使用字体 token。统一高度、圆角、行高、边框、间距和焦点，不用页面位置推导控件类型。

## 6. JavaScript 和数据结构方案

### 6.1 模块边界

core 已提供纯业务函数，app 仍同时承担状态、存储、导航、HTML、编辑、导入、剪贴板、压缩、长按动画和布局同步。资讯 UI 直接移动 app DOM，多个模块依赖全局对象和固定顺序。

建议逐步提取：

| 模块 | 职责 |
|---|---|
| domain/date-calendar | 日期、工作日规则和年度来源 |
| domain/records | 记录优先级、完整性、工时、请假 |
| domain/statistics | 汇总、目标、出勤、累计口径 |
| domain/imports | 解析、冲突计划、已接受记录和回放 |

过渡期保留普通 IIFE 和单一显式命名空间，WorkTime 作为兼容门面。先提取纯函数，再提取副作用，最后缩短 app。拆模块不需要引入框架或改变双击使用方式。

### 6.2 数据契约和不变量

用 JSDoc 定义 State/Settings/Day/OAObservation/ManualRecord/Draft/ImportLog/TimeTemplate，明确 null、缺失、0、空字符串语义。分钟作为内部单位，显示时转小时；写明加班要求的小数精度。

备份流程：decode → migrate → normalize → validate → preview → commit。错误带字段路径。要求：接受结果可再次恢复；计算和来源不变；拒绝冲突不复活；旧自定义休息时段不无说明覆写。

actual/estimate/draft 对应的“手动填写”产品语义需要单独文档，不能把 estimate 全部理解成未来预测。summary 与累计平均的分母目前不同，默认保持并分别命名，业务口径修改另做独立变更。
